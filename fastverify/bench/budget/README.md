# bench/budget — resource budgets of the sound verifier

What every stage of `--preset sound` and of the export-in trusted check needs in memory and CPU, measured under real
cgroup-v2 limits (laptop / CI-runner / shared-node profiles), how the pipeline behaves when the limit is hit (it must
never turn a memory kill into a verdict), and a memory model + host-limit reader that the orchestrator and
`--preset sound-auto` can use to pick threads and items. Big inputs (exports, build trees) are regenerated by the
package; only the small cgrun JSONs of the measured matrix are kept under `results/` (read by `tests/budget/run.sh`;
the coefficients of `lib/budget.py` were fitted from them).

| file | what |
|---|---|
| `cgrun.sh` | run one command under cgroup-v2 limits and record what it used: thin wrapper over a site-provided scope launcher (`cgrun`, path in `CGRUN_TOOL`; a transient systemd scope: `memory.max` with swap 0, `AllowedCPUs`, `TasksMax`) that runs `cgrun-inner.sh` inside the scope |
| `cgrun-inner.sh` | inside the scope: samples the scope's own cgroup (`memory.current`, anon/file/shmem from `memory.stat`, every `--sample` s -> `--timeline`), optionally every process's RSS (`--ps` s -> `top_procs`, `max_rss_by_comm`), runs the command, writes ONE JSON: limits as read from the cgroup, exit code, wall, `memory.peak`, `memory.events` (oom, oom_kill, max), `cpu.stat`, `pids.peak`, `scope_terminated` |
| `sweep_check.sh OUT LABEL INDIR CPUBASE "T..." [MEM...]` | the export-in trusted check (`check/sound/check-sound.sh`) once per thread count, then once per memory limit; restartable (a run whose JSON exists is skipped) |
| `legs.sh OUT LABEL INDIR CPUBASE "T..." [LEGS]` | each leg ALONE (pleanchecker `-jT`, gruszka `EXPORT T`, ccmp with stub kernels = parse + compareAt + checkAxioms only) from the pinned binaries of `check/sound/pins.env` (sha256 re-checked); measurement only, no verdict recorded anywhere |
| `run_fv.sh OUT TAG CPUS MEM THREADS PROJECT CHALLENGE [args]` | one `bin/fastverify` run from sources under limits (+ `result.json` copy) |
| `swarm_check.sh OUT TAG INDIR N THREADS CPUS MEM` | N concurrent checks inside ONE limited scope = N clients sharing a machine / CI runner |
| `summarize.py DIR...` | one table row per cgrun JSON (`--tsv`) |
| `fit.py sizes.json DIR...` | least-squares fit `peak = a*export_bytes + b*threads + c` per stage from the JSONs (numpy-free) |
| `lib/budget.py host\|estimate\|plan` (package file) | the host-limit reader (cgroup chain: memory.max/high/current, cpu.max, cpuset, affinity, MemAvailable, /dev/shm) + the fitted model + a thread planner under a memory budget |
| `fvbudget.sh CHALLENGE OUT --from-export FILE [args]` | export-in verification under THIS process's budget: `lib/budget.py plan` picks the thread count that fits the cgroup/host memory for the export's size, then `bin/fastverify --preset sound --from-export` |
| `kill_one_lean.sh OUT TAG CPUS T PROJECT CHALLENGE DELAY [args]` | OOM-kill simulation for the official build path: SIGKILL one `lean` of the run DELAY s into the build, record the verdict and the build's classification |
| `e1_measure.sh OUT TAG PROJ_TREE MODULE TARGETS T` | the native exporter E1 alone on an existing build tree, inside a measured scope (export-stage peak) |
| `mk_attempt.sh DIR WS` | a one-module `import Mathlib` proof attempt (project + challenge) for the laptop attempt case |
| `fvserve_profile.sh STATE PSET ATTEMPTS OUT [N] [CONC]` | latency (one attempt at a time) and burst throughput of a running `tools/fvserve` with the service scope's memory |
| `frontier.py EXPORT --targets ...` | untrusted sorry-frontier LEDGER of an export (pure-sorry frontier theorems, partial proofs, sorried definitions, extra axioms) used for the FLT history case; the verdict comes from `check/frontier/check-frontier.sh` |
| `sizes.json` | export sizes of the labels used in the run names |
| `results/` | the cgrun JSONs (small) of the measured matrix, one subdirectory per experiment |

Every script writes its cgrun JSON, logs and copied `result.json` under the `OUT` directory given on its command line.

Method notes. `memory.peak` of a cgroup counts anonymous memory AND the page cache the job touched (file-backed pages
are reclaimable, so a run can still pass at a `memory.max` below its unlimited peak). A forked child's RSS includes
copy-on-write pages shared with its parent (in the zygote build every `lean` child shows the zygote's memory); the
cgroup charges them once. For clean timings keep a run's cpuset off SMT siblings and do not run two timed jobs on
siblings; memory numbers do not care. With a transient systemd scope the default `OOMPolicy` is stop: when the kernel
OOM-kills one process the whole job gets SIGTERM, so the orchestrator's fallback after a kill (B3 -> B1 -> B0, a check ->
DECLINED) can only be observed with `OOMPolicy=continue` or in a delegated cgroup where only the offending process dies.

### Lean 4.37.0-rc1 path

* `evict.py DIR|FILE ...` - drops the clean page-cache pages of the given files (`posix_fadvise DONTNEED`, no privileges);
  run it before a "cold cache" row so the scope's `memory.peak` charges the olean reads to the measured scope.
* `attempt_caps.sh OUT PROJ CHAL WS CPUS THREADS "MEM..."` - cold-cache cap sweep of one attempt project (evicts the
  workspace, toolchains and project before every run, then `run_fv.sh`); rows `OUT/<name>.c<T>.m<GB>.cold.*`.
* `sweep_check.sh` honours `CHECK_SH` (another check-sound.sh, e.g. a staged 4.37 one inside a package view) and
  `CHECK_ARGS` (e.g. `--pins check/sound/pins-437.env`); default = the package's `check/sound/check-sound.sh`.
* `mkreport.py RESULTS_DIR` - markdown tables from the cgrun JSONs; section G = the 4.37 rows (`fv-attempt437.*`,
  `sw-chal437*.*`).
* `continue_build.sh`, `export_kept.sh` - example job wrappers for a large multi-core host (site-specific paths; adapt
  before use): continuation of a kept official build tree after an external stop, and the native 4.37 export of the result.
