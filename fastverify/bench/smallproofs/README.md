# bench/smallproofs — one-theorem projects on top of the cached Mathlib

The small end of the generality study: many small, independent, competition / AI-prover style proofs, each a
one-theorem project against its own clean challenge, through the official flow and the fast presets. Big inputs
(exports, build trees) are regenerated by the scripts; each run writes into the `OUT` / root directory given on the
command line.

| file | what |
|---|---|
| `problems.py` | the corpus spec: `(id, style, imports, statement, proof[, preamble])`; 117 problems in 20 proof styles (92 `import Mathlib`, 1 narrow import, 24 core-only), the kernel-cost series `ks20..ks50` / `ke20, ke30`, 4 negatives `xk01..xk04` (false `decide +kernel` claims, expected REJECTED), 6 failing attempts `xe01..xe06` (proofs that do not elaborate, expected REJECTED), 9 definition-style problems `di*/dm01/du01/dt*/dw01` (definitions in a preamble shared by challenge and solution), 32 same-statement variants `s<k>_<style>` (7 statements x 3-6 styles); 186 cases with the batches |
| `gen.py OUT [TOOLCHAIN]` | writes `OUT/challenges/<id>` (statement with `sorry`, `comparator.json`, lakefile, manifest) and `OUT/projects/<id>` (the proof) + batches `bM` (all 92 Mathlib problems in one module), `bM10a..j` (slices of 10), `bC` (24 core problems), `cases.json`; with `TOOLCHAIN` (e.g. `leanprover/lean4:v4.36.0`) only the core-only problems |
| `run1.sh CORPUS CASE PRESET OUT THREADS src|given [args]` | one `bin/fastverify` run (`src`: the challenge is built officially in the run; `given`: the official challenge export of an earlier reference run, pinned with `--challenge-sha256`) |
| `mkgiven.sh CORPUS OUT CASE` | `OUT/given/CASE` = challenge dir + the official challenge export the reference run built |
| `lane.sh` / `lane2.sh` / `lane3.sh` | per case: reference -> given -> `sound,fast-exact` (lane.sh); `sound`, `sound --build B0`, `fast-exact` (lane2.sh); failing attempts: + `sound --no-confirm-build-failure` (lane3.sh) |
| `ablate.sh` / `ablate2.sh` | fixed-cost ablation of the sound preset on one case: (ablate.sh) sound / `--unsafe skip-kernel-tc,linter-off` / `--build B1` / `--build B0` / no overlap / reference / fast-exact; (ablate2.sh) sound / without the zygote items / PGO-only minimal / `--build B0` / export-in; N repeats |
| `threads.sh` | `--preset sound` at `--threads 1/2/4` |
| `profile.sh` | official Lean 4.33.1 with `-Dprofiler=true` on every case (bwrap via `leandev.sh`) |
| `collect.py`, `anatomy.py`, `ablsum.py`, `profsum.py`, `verdicts.py`, `mdtables.py`, `fit.py`, `sametable.py`, `stages.py` | result tables (per-stage seconds, intrinsic work vs fixed cost, profiler categories, differential verdict tally, markdown per case / per style, linear model per configuration, same-statement table) |
| `leandev.sh DIR FILE` | elaborate one file with the official toolchain + the trusted workspace inside bwrap (no network, home hidden) |
| `trace_cs.sh` | the unchanged `check/sound/check-sound.sh` under `bash -x` with timestamps (where its fixed cost goes) |
| `test/sound-smallproofs.sh [WORK]` | regression test (`tests/smallproofs`): reference vs `--preset sound` on core-only cases + the negatives (+ Mathlib cases when the workspace exists) |

Example (any host with the package installed):
```
python3 -I gen.py $SCRATCH/sp/corpus
./lane2.sh $SCRATCH/sp/corpus $SCRATCH/sp 32 nn01 om05 ks40        # reference, sound, sound --build B0
python3 -I anatomy.py $SCRATCH/sp/corpus anat.tsv $SCRATCH/sp/runs
python3 -I collect.py $SCRATCH/sp/corpus table.tsv $SCRATCH/sp/summary.tsv:$SCRATCH/sp/runs
python3 -I mdtables.py anat.tsv table.tsv --per-case
```
NFS caveat: on hosts where the official toolchains and the Mathlib workspace live on NFS every official `lean`
process pays NFS latency, which biases official-vs-fast comparisons; use local disks or `bench/shapes/mklocal.sh`.
