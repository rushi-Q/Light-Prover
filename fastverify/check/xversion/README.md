# Cross-version gate (`check/xversion/`)

The sound judge runs the Lean 4.36 comparator judge code and the official 4.36 kernel (or, with `pins-437.env`, the
4.37.0-rc1 ones). Most projects are on other releases: their challenge export comes from release R's official Lean. This
gate decides whether the judge may judge an export of release R, and applies the extra rules of R's own comparator. It
runs inside every judge script and in the orchestrator; passing it never decides a verdict, it only lets the unchanged
judge decide.

`xvcheck.py CHALLENGE_EXPORT COMPARATOR_JSON` reads R (`lean.version` and `lean.githash`) strictly from the meta line of
the pinned challenge export. Exit 0: R is admitted; 1: REJECTED by an extra rule of R's comparator (4.37: "Challenge
definition is not sorried"); 2: R is not admitted (no verdict). 45 releases are admitted, v4.26.0-rc1 to v4.37.0-rc1.

## Why the 4.36 judge may judge an export of release R

The statement comparison, the axiom check and the second kernel do not depend on the release as long as the judge code
is the code R's own comparator runs. The only release-dependent assumption is in the kernel: it does not check the
definitions of a few constants it treats specially (GMP-accelerated `Nat` operations on literals, string literals, `Quot`
and its eliminators) but assumes their meaning. The comparator therefore compares these primitive targets: the
solution's definitions must equal the official ones of R. If R's kernel extension code equals 4.36's, the 4.36 kernel
judges an R environment under exactly the assumption that R's official verdict relies on.

`releases.json` is generated by `mkreleases.py` from the Lean sources of every release. A release is admitted only if
all mechanical checks hold: the set of accelerated `Nat` operations equals 4.36.0's; the kernel's persistent
constants equal 4.36.0's, up to the native-reduction constants that the 4.36 kernel cannot reduce and `checkAxioms`
rejects anyway; string literals unfold to `String.ofList` (releases before 4.26 unfold to `String.mk`, which is
why they are refused); `quot.cpp` / `quot.h` equal 4.36.0's; the comparator judge sources and primitive-target lists
equal 4.36.0's or a reviewed variant (4.37.0-rc1, with its extra rule); and the export format is 3.1.0. Releases without
a `lake comparator` (4.34 and earlier) are judged by the 4.36 judge code, which is at least as strict as theirs.

The gate reads the challenge export and the configuration with exact parsers: an unknown or malformed meta line, an
unlisted release or a configuration it cannot read is no verdict. Every rule of the gate can only add a refusal or a
rejection. The Riemann Hypothesis verdicts are an instance: a Lean 4.33.1 challenge judged by the 4.36 judge.

## Tests

`test/run.sh [WORK]` (unit cases on synthetic exports and end-to-end cases with the official 4.35.0 and 4.37.0-rc1
toolchains when present); the cross-version differential `diff/` (the Mathlib-differential cases re-targeted to release R,
R's own official flow against the gate and the judge on the same exports).
